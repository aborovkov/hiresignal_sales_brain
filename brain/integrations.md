# 1. Входной поток: откуда брать отклики

## 1.1 LinkedIn напрямую - закрыт

- Получение списка откликнувшихся через API доступно **только одобренным партнёрам** LinkedIn Talent Solutions: критерии отбора, подписанное API-соглашение, ограничения на использование данных, вызовы не чаще раза в час.
- Автоматизация Easy Apply официально **не поддерживается** вообще.
- Скрейпинг - нарушение ToS и риск блокировки аккаунта.

**Вывод:** как основной канал не годится. Не строить на этом продукт.

## 1.2 Gmail → n8n → attachment - рабочий обход (план Алексея)

Джоб-борды, включая LinkedIn, присылают отклик письмом на почту работодателя. Мы читаем **свой собственный ящик** - это легитимно и не упирается в чужой API.

Флоу: Gmail trigger в n8n → новое письмо → парсинг → извлечение CV из вложения → передача в пайплайн StepUP.

**Плюсы:** быстрее всего до MVP, не требует ничьего разрешения, работает поверх любого источника, который умеет слать письма.

**Подводные камни, которые всплывут сразу:**
- LinkedIn часто присылает **ссылку на профиль, а не PDF**. Парсер вложений на таких письмах вернёт пусто - нужен фолбэк.
- Форматы писем меняются без предупреждения; парсер будет ломаться молча.
- Дедупликация: один кандидат может прийти письмом дважды и из двух источников.
- Атрибуция вакансии: из письма не всегда однозначно, на какую позицию отклик.
- Почтовый ящик как хранилище персданных кандидатов - отдельный вопрос по GDPR (см. §3).

## 1.3 Нативный ATS - Ashby как первый таргет

Открытый Developer API: **164 операции**, HTTP Basic Auth, **22 типа вебхуков**, включая `applicationSubmit`, `applicationUpdate`, `candidateStageChange`, `candidateHire`. Есть создание кандидатов из внешних источников и партнёрская программа с процессом онбординга интеграций.

**Почему именно Ashby первым:** у нас уже есть активный design partner на Ashby (`../crm/accounts/david-stepania.md`), то есть интеграция сразу получает живого пользователя и живой поток данных, а не гипотетического.

## 1.4 Unified API - Merge / Kombo (прямой ответ на C3)

Интегрируешься один раз - получаешь десятки ATS.

| | Merge | Kombo |
|---|---|---|
| Охват | ~63 ATS, sync-and-store | глубже по **Европе** |
| Сильная сторона | зрелость, enterprise | **специалист по assessment-флоу внутри ATS**: 17 assessment-коннекторов (Greenhouse, Lever, SmartRecruiters, Ashby, Recruitee, Teamtailor) |
| Операции | чтение jobs / candidates / applications | плюс запись обратно: новые заявки, смена стадий, вложения |

Kombo профильнее под нашу задачу: мы по сути и есть assessment-вендор, которому надо встроиться в чужой ATS и **записать результат обратно** в карточку кандидата - ровно то, что просили клиенты в гипотезе C3.

**Стратегический выбор:** Ashby нативно = глубина и один счастливый design partner. Unified API = ширина и снятие C3 как блокера для всей воронки. Это не или-или по смыслу, но по деньгам на старте - да.

# 2. Исходящий канал: как связываться с кандидатом

## WhatsApp Business API

Технически возможно, но это не «просто пишем кандидату»:

- Первое сообщение тому, кто не писал нам первым, идёт **только заранее одобренным шаблоном**. Модерация 24-72 часа.
- Шаблоны должны быть **utility, не промо**: уведомление о вакансии, статус, напоминание об интервью.
- Обязательны: идентификация компании, цель сообщения, инструкция по отписке.
- После ответа кандидата открывается **24-часовое окно** свободной переписки; вне окна - снова шаблон.
- **Opt-in шаблон - самое ценное здесь не технически, а юридически:** он создаёт paper trail согласия. Это прямо помогает с GDPR и заодно отсекает тех, кто откликнулся и забыл.

**Вывод:** канал рабочий и под него есть подтверждение ценности из кастдевов, но заложить надо не «отправку сообщений», а согласие, шаблоны, окна и хранение переписки в системе, а не в чьём-то телефоне.

# 3. Регуляторика - самое срочное

## 3.1 EU AI Act: high-risk режим уже действует

- Найм = **high-risk** по Annex III §4. Это прямо включает скрининг CV, ранжирование резюме и **скоринг интервью**.
- **Полное применение high-risk обязательств наступило 2 августа 2026** - то есть режим уже живой, не «когда-нибудь».
- Обязательства: риск-оценка, техдокументация, **human oversight**, bias testing, прозрачность (кандидата надо уведомить, что решение принимается с участием AI), регистрация в базе ЕС, непрерывный мониторинг.
- Штрафы: до €35M или 7% глобального оборота. Вендоры вне ЕС, нанимающие в ЕС, **в скоупе**.

## 3.2 Запрет на распознавание эмоций - бьёт по нашей гипотезе D5

Распознавание эмоций в интервью **запрещено с 2 февраля 2025**.

Наша гипотеза D5 (`hypotheses.md`) предлагает собирать задержку до ответа, паузы, длительность и темп речи. Здесь проходит тонкая, но принципиальная граница:

- **Скорее допустимо:** трактовать тайминг как признак того, что ответ читается с подготовленного текста (проверка авторства claim'а).
- **Запрещено:** выводить из тех же сигналов эмоции, уверенность, нервозность кандидата.

D5 нельзя строить, не определившись с формулировкой. Помечено прямо в `hypotheses.md`.

## 3.3 Наложение на уже проверенное

B5 (GDPR как реальный блокер для EU) в `hypotheses.md` уже стоит ✅ - подтверждена тремя независимыми источниками. AI Act ложится сверху и делает EU-сегмент **ещё дороже на входе**. Оценка «$3-4k на GDPR-пакет» из планов в Data Room покрывает DPA и хостинг, но **не покрывает** high-risk обязательства AI Act (bias testing, техдокументация, регистрация). Бюджет надо пересчитать.
